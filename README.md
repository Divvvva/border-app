# 🚌 Брест – Тересполь: очередь автобусов и прогноз

Личный проект: мониторинг очереди на границе Беларусь – Польша (Брест – Тересполь)
в обе стороны и прогноз на 7 дней. Главное направление — выезд из Беларуси.

## Как устроено

```
GitHub Actions (каждые 15 мин) → collector.py → data/queue.csv
                                                     ↓
                     Streamlit Cloud → app.py ← model.py (прогноз)
```

| Файл | Что делает |
|---|---|
| `collector.py` | Собирает очередь: электронная очередь РБ (выезд), резерв — сайт ГПК, Nakordoni (въезд) |
| `model.py` | Профиль «день недели × час» + праздники + затухание текущего отклонения; ожидание = очередь / пропускная способность |
| `app.py` | Приложение: сейчас, график 7+7 дней, лучшее время, тепловая карта, «Мой рейс» |
| `config.py` | Все настройки (адреса, время в пути, праздники) |
| `tests/test_all.py` | Проверка парсеров и модели без интернета: `python -m tests.test_all` |

## Прогноз на мои даты заранее

В `config.py` в списке `MY_TRIPS` задаются поездки: дата, время отправления,
направление и время в пути. При каждом сборе `predict_targets.py` пересчитывает
прогноз на момент, когда автобус будет на границе, и дописывает его в
`data/forecast_log.csv`. В приложении блок «Мои поездки» показывает текущий
прогноз и график того, как он менялся: чем ближе дата и чем больше истории,
тем у́же интервал. Горизонт — до 60 дней.

- Дальше 7 дней: профиль «день недели × час» за 8 недель × праздничный коэффициент ×
  тренд последней недели.
- Ближе 7 дней: почасовой прогноз с учётом текущей ситуации на границе.
- Праздничный коэффициент сначала — предположение (×1,3). С 20 декабря модель
  начнёт видеть реальные праздничные дни и пересчитает его по данным.

## Запуск: пошагово

**1. Репозиторий.** github.com → New repository → `border-app` → **Public**
(для публичных репозиториев GitHub Actions бесплатные без лимита) → Create.
Загрузи все файлы из архива (Add file → Upload files). Папку `.github` тоже:
её проще загрузить через GitHub Desktop или `git push`, так как веб-загрузка
скрытых папок иногда не срабатывает. Проверь, что в репозитории есть
`.github/workflows/collect.yml`.

**2. Права для бота.** Settings → Actions → General → Workflow permissions →
**Read and write permissions** → Save.

**3. Первый запуск.** Вкладка Actions → `collect-border-queue` → **Run workflow**.
Через минуту в репозитории появятся `data/queue.csv` и `data/raw/`.

**4. Проверь данные (важно!).** Открой лог запуска (Actions → запуск → Collect):
там видно, сколько автобусов и легковых собрано.
- Если источник `belarusborder` сработал — отлично, это лучший вариант
  (есть даже, сколько уже стоят машины).
- Если в логе ошибка `belarusborder` и данные пришли из `gpk` — проверь порядок
  чисел: открой страницу Бреста на gpk.gov.by, сравни три числа «exit from RB»
  с иконками и при необходимости поправь `GPK_NUMBER_ORDER` в `config.py`.
- Если не сработало ничего — пришли мне файлы из `data/raw/` и текст ошибки.

**5. Въезд в Беларусь (по желанию).** Зарегистрируйся как разработчик на nakordoni.eu,
найди id перехода Тересполь → Брест через `/api/v1/data/checkpoints`.
Settings → Secrets and variables → Actions → New secret:
`NAKORDONI_API_KEY` и `NAKORDONI_PPID_ENTRY`.

**6. Приложение.** share.streamlit.io → войти через GitHub → Create app →
выбрать репозиторий, файл `app.py` → Deploy. Получишь ссылку, которая
открывается и с телефона. Данные подтягиваются из репозитория автоматически
(Streamlit перезапускается при каждом новом коммите с данными).

## Вариант на GitLab

1. Новый проект (Public) на gitlab.com, загрузи файлы. Файл `.gitlab-ci.yml` уже в корне,
   папку `.github` можно удалить.
2. Токен для сохранения данных: Settings → Access tokens → Add new token,
   роль **Maintainer**, scope **write_repository**. Скопируй токен.
3. Settings → CI/CD → Variables → Add variable: `GITLAB_PUSH_TOKEN` = токен,
   галочка **Masked**, галочку Protected сними (или сделай ветку main protected).
   Сюда же при желании `NAKORDONI_API_KEY` и `NAKORDONI_PPID_ENTRY`.
4. Build → Pipeline schedules → New schedule → cron `0 * * * *`, часовой пояс Prague → Save.
   Проверь кнопкой ▶ (Run).
5. **Лимит:** у бесплатного GitLab 400 минут CI в месяц. Один запуск ≈ 0,5 мин,
   раз в час ≈ 360 мин в месяц — впритык. Следи в Settings → Usage quotas.
   Если не хватает — поставь `0 */2 * * *` (раз в 2 часа).
6. **Приложение.** Streamlit Community Cloud работает только с GitHub. Варианты:
   - Settings → Repository → Mirroring repositories → push-зеркало на GitHub,
     и дальше Streamlit Cloud как в шаге 6 выше (самое простое);
   - или задеплоить `app.py` на Render / любой хостинг с переменной окружения
     `DATA_URL` = raw-ссылка на `data/queue.csv` в GitLab
     (`https://gitlab.com/<логин>/<проект>/-/raw/main/data/queue.csv`).

## Что важно знать

- Прогноз становится полезным примерно через 1–2 недели сбора. Запусти как можно раньше.
- Рейсовые автобусы могут проходить вне электронной очереди, тогда число
  автобусов в ней занижено. В этом случае смотри на легковые как на индикатор загрузки.
- Пропускная способность по умолчанию: 2 автобуса/ч и ~98 легковых/ч (2350 в сутки по ГПК).
  Через несколько дней модель заменит это оценкой по реальным данным.
- GitHub может запускать расписание с задержкой 5–30 минут — это нормально.
